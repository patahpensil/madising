# Restricted account staging

The /account route signs in with independent synthetic credentials. Only PAT and CUR may self-register; both remain pending. Trusted staging operator provisioning is not actual Admin/Owner approval or clinical credential verification. There are no real contact fields, MFA, OIDC, clinical license or recovery flows. No production activation.

Apply migrations 001, 002 and 003 to a disposable PostgreSQL database with a restricted user. Enable MADISING_TRIAL_ENABLED=1 and MADISING_ACCOUNT_TRIAL=1 on API; set TRIAL_DATABASE_URL on API only. Enable MADISING_ACCOUNT_TRIAL=1 and set TRIAL_WEB_ORIGIN to the exact protected HTTPS origin on Next.js. Both bind loopback. Set MADISING_FIXTURE_HARNESS=1 only in isolated CI/local regression, never shared staging. Require Cloudflare Access and Tunnel on a dedicated origin before enabling outside loopback. Do not expose PostgreSQL or NestJS ports. Public static preview remains independent.

Provision with node apps/staging-api/scripts/provision-account.mjs ROLE SYNTHETIC_USERNAME [EXERCISE_UUID], using TRIAL_ACCOUNT_PASSWORD supplied through protected environment, not command arguments. First account creates a two-hour exercise; other accounts may be assigned to the exercise via its UUID. Separate credentials are required for each role. No credentials are committed or printed. Expired exercise accounts are disposable; an operator may purge expired exercises while the service is stopped. Account provisioning is not a production privilege.

Security: scrypt N=32768,r=8,p=1, salted password hashes, two concurrent password operations per process, five failed attempts lock for fifteen minutes, 256-bit opaque session tokens hashed at rest, login rotation, logout revocation, thirty-minute idle and two-hour maximum. HTTPS cookie HttpOnly, Secure, SameSite Strict, exact origin check; role and exercise resolved from locked server records, not browser. Single process cap is not distributed abuse protection; gateway rate limits and proper identity provider, MFA, audit, and privilege lifecycle review are mandatory for a future real identity system. No production readiness claim. Dependency lockfiles, penetration testing and stress/heap profiling remain open.

Verification: database tests cover pending registration, cross-role forgery, simultaneous acceptance, revocation, login rotation and lockout. Browser test uses independent browser contexts, HttpOnly cookie, shared exercise, separate role actions and logout. Results to be recorded from CI. No RME/SATUSEHAT or real payment calls.
